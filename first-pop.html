Aprendiendo Rust con Demasiadas Listas Enlazadas

Pop

Al igual que push, pop quiere mutar la lista. A diferencia de push, realmente queremos devolver algo. Pero pop también tiene que lidiar con un caso límite complicado: ¿qué pasa si la lista está vacía? Para representar este caso, usamos el confiable tipo Option:

pub fn pop(&mut self) -> Option<i32> {
    // TODO
}

Option<T> es un enum que representa un valor que puede existir. Puede ser Some(T) o None. Podríamos crear nuestro propio enum para esto como hicimos con Link, pero queremos que nuestros usuarios puedan entender qué demonios es nuestro tipo de retorno, y Option es tan ubicuo que todo el mundo lo sabe. De hecho, es tan fundamental que se importa implícitamente en el ámbito de cada archivo, así como sus variantes Some y None (para que no tengamos que decir Option::None).

Los picos en Option<T> indican que Option es en realidad genérico sobre T. ¡Eso significa que puedes hacer un Option para cualquier tipo!

Así que eh, tenemos este Link, ¿cómo averiguamos si está Empty o tiene More? ¡Pattern matching con match!

pub fn pop(&mut self) -> Option<i32> {
    match self.head {
        Link::Empty => {
            // TODO
        }
        Link::More(node) => {
            // TODO
        }
    };
}

Ups, pop tiene que devolver un valor, y todavía no lo estamos haciendo. Podríamos devolver None, pero en este caso probablemente es mejor devolver unimplemented!(), para indicar que no hemos terminado de implementar la función. unimplemented!() es una macro (! indica una macro) que entra en pánico (panic) en el programa cuando llegamos a ella (~lo bloquea de forma controlada).

pub fn pop(&mut self) -> Option<i32> {
    match self.head {
        Link::Empty => {
            // TODO
        }
        Link::More(node) => {
            // TODO
        }
    };
    unimplemented!()
}

Los pánicos incondicionales son un ejemplo de una función divergente. Las funciones divergentes nunca retornan a quien las llamó, por lo que pueden usarse en lugares donde se espera un valor de cualquier tipo. Aquí, unimplemented!() se está usando en lugar de un valor de tipo Option<T>.

Nótese también que no necesitamos escribir return en nuestro programa. La última expresión (básicamente línea) en una función es implícitamente su valor de retorno. Esto nos permite expresar cosas realmente simples de forma más concisa. Siempre puedes retornar explícitamente con return como en cualquier otro lenguaje tipo C.

Hurra, ¡compila otra vez! Ahora resolvamos esa lógica. Queremos hacer un Option, así que creemos una variable para eso. En el caso Empty necesitamos devolver None. En el caso More necesitamos devolver Some(i32), y cambiar la cabeza de la lista. Así que, ¿intentemos hacer básicamente eso?

pub fn pop(&mut self) -> Option<i32> {
    let result;
    match &self.head {
        Link::Empty => {
            result = None;
        }
        Link::More(node) => {
            result = Some(node.elem);
            self.head = node.next;
        }
    };
    result
}

cabeza

escritorio

Estamos intentando mover algo de node cuando todo lo que tenemos es una referencia compartida a él.

Deberíamos dar un paso atrás y pensar qué estamos intentando hacer. Queremos:

  • Comprobar si la lista está vacía.
  • Si está vacía, simplemente devolver None.
  • Si no está vacía
    • eliminar la cabeza de la lista
    • eliminar su elem
    • reemplazar la cabeza de la lista con su next
    • devolver Some(elem)

La idea clave es que queremos eliminar cosas, lo que significa que queremos obtener la cabeza de la lista por valor. Ciertamente no podemos hacerlo a través de la referencia compartida que obtenemos con &self.head. También "solo" tenemos una referencia mutable a self, así que la única forma de mover cosas es reemplazarlas. ¡Parece que estamos haciendo el baile de Empty otra vez!

Probemos:

pub fn pop(&mut self) -> Option<i32> {
    let result;
    match mem::replace(&mut self.head, Link::Empty) {
        Link::Empty => {
            result = None;
        }
        Link::More(node) => {
            result = Some(node.elem);
            self.head = node.next;
        }
    };
    result
}

O M G

¡Compiló sin ninguna advertencia!

En realidad, voy a aplicar mi propia regla aquí: creamos este valor result para devolverlo, pero en realidad no necesitábamos hacer eso en absoluto. Así como una función se evalúa a su última expresión, cada bloque también se evalúa a su última expresión. Normalmente suprimimos este comportamiento con punto y coma, que en su lugar hace que el bloque se evalúe a la tupla vacía, (). Este es en realidad el valor que devuelven las funciones que no declaran un valor de retorno — como push.

Así que, en su lugar, podemos escribir pop como:

pub fn pop(&mut self) -> Option<i32> {
    match mem::replace(&mut self.head, Link::Empty) {
        Link::Empty => None,
        Link::More(node) => {
            self.head = node.next;
            Some(node.elem)
        }
    }
}

Que es un poco más conciso e idiomático. Nótese que la rama Link::Empty ha perdido completamente sus llaves, porque solo tenemos una expresión que evaluar. Solo una abreviatura útil para casos simples.
