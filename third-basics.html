Aprendiendo Rust con Demasiadas Listas Enlazadas

Conceptos Básicos (Basics)

Ya conocemos muchos de los conceptos básicos de Rust, así que podemos hacer muchas de las cosas simples otra vez.

Para el constructor, podemos nuevamente copiar y pegar:

impl<T> List<T> {
    pub fn new() -> Self {
        List { head: None }
    }
}

push y pop ya no tienen mucho sentido. En su lugar podemos proporcionar prepend y tail, que proporcionan aproximadamente lo mismo.

Empecemos con prepend (anteponer). Toma una lista y un elemento, y devuelve una Lista. Como en el caso de la lista mutable, queremos hacer un nuevo nodo, que tenga la lista anterior como su valor next. Lo único novedoso es cómo obtener ese valor next, porque no se nos permite mutar nada.

La respuesta a nuestras oraciones es el trait Clone. Clone es implementado por casi todos los tipos, y proporciona una forma genérica de obtener "otro como este" que sea lógicamente disjunto, dado solo una referencia compartida. Es como un constructor de copia en C++, pero nunca se invoca implícitamente.

Rc en particular usa Clone como la forma de incrementar el contador de referencias. Así que en lugar de mover un Box para estar en la sublista, simplemente clonamos la cabeza de la lista anterior. Ni siquiera necesitamos hacer match en la cabeza, porque Option expone una implementación de Clone que hace exactamente lo que queremos.

Muy bien, intentémoslo:

pub fn prepend(&self, elem: T) -> List<T> {
    List { head: Some(Rc::new(Node {
        elem: elem,
        next: self.head.clone(),
    }))}
}

tail es la inversa lógica de esta operación. Toma una lista y devuelve toda la lista con el primer elemento eliminado. Todo lo que es es clonar el segundo elemento en la lista (si existe). Probemos:

pub fn tail(&self) -> List<T> {
    List { head: self.head.as_ref().map(|node| node.next.clone()) }
}

Hrm, nos equivocamos. map espera que devolvamos una Y, pero aquí estamos devolviendo un Option<Y>. Afortunadamente, este es otro patrón común de Option, y podemos usar and_then para permitirnos devolver un Option.

pub fn tail(&self) -> List<T> {
    List { head: self.head.as_ref().and_then(|node| node.next.clone()) }
}

> cargo build

Genial.

Ahora que tenemos tail, probablemente deberíamos proporcionar head, que devuelve una referencia al primer elemento. Eso es simplemente peek de la lista mutable:

pub fn head(&self) -> Option<&T> {
    self.head.as_ref().map(|node| &node.elem)
}

> cargo build

Bien.

Esa es suficiente funcionalidad para probarlo:

#[cfg(test)]
mod test {
    use super::List;

    #[test]
    fn basics() {
        let list = List::new();
        assert_eq!(list.head(), None);

        assert_eq!(list.head(), Some(&3));

        let list = list.tail();
        assert_eq!(list.head(), Some(&2));

        let list = list.tail();
        assert_eq!(list.head(), Some(&1));

        let list = list.tail();

Iter también es idéntico a como era para nuestra lista mutable:

pub struct Iter<'a, T> {
    next: Option<&'a Node<T>>,
}

impl<T> List<T> {
    pub fn iter(&self) -> Iter<'_, T> {
        Iter { next: self.head.as_deref() }
    }
}

impl<'a, T> Iterator for Iter<'a, T> {
    type Item = &'a T;

    fn next(&mut self) -> Option<Self::Item> {
        self.next.map(|node| {
            self.next = node.next.as_deref();
            &node.elem
        })
    }
}

#[test]
fn iter() {
    let list = List::new().prepend(1).prepend(2).prepend(3);

    let mut iter = list.iter();
    assert_eq!(iter.next(), Some(&3));
    assert_eq!(iter.next(), Some(&2));
    assert_eq!(iter.next(), Some(&1));
    assert_eq!(iter.next(), None);
}
